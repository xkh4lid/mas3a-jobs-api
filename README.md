# مَسعى — خدمة جلب الوظائف

خدمة Cloudflare Worker مستقلة لموقع مَسعى، مبنية على آخر ملف `mas3a-worker-v2.js` بتاريخ 5 أكتوبر 2026.

اسم Worker المقصود: `mas3a-jobs-api`.

## الملفات

- `src/index.js`: كود النسخة الثانية كاملًا.
- `migrations/0001_init.sql`: جداول الوظائف والمصادر وسجل المزامنة.
- `wrangler.example.toml`: نموذج إعداد Worker وجدولة كل ساعة عند الدقيقة 17.
- `package.json`: أوامر الفحص والتطوير والنشر.

## ما تفعله الخدمة

- تفحص صفحات التوظيف الرسمية لـ stc وKAUST.
- تعرض في `/api/jobs` الوظائف التي نجح التحقق منها فقط، مع وقت المزامنة وآخر نتيجة.
- يعرض `/api/health` حالات المصادر وأخطاء الفحص وآخر تشغيل.
- تعالج الصفحات المغلقة وتؤرشف الوظائف التي لم ينجح التحقق منها منذ سبعة أيام.

المصادر الحكومية والعسكرية ليست موصلات آلية مضافة إلى هذه النسخة. نجاح رفع الكود إلى GitHub لا يثبت نجاح مزامنة المصادر على Cloudflare.

## تجهيز النشر على Worker الحالي

1. ثبّت الحزم باستخدام `npm install`.
2. انسخ `wrangler.example.toml` إلى `wrangler.toml`.
3. أدخل اسم ومعرّف قاعدة D1 الموجودة والمرتبطة بالـWorker الحالي في `database_name` و`database_id`. أبقِ اسم الربط `DB`.
4. سجّل الدخول إلى حساب Cloudflare الذي يملك Worker باستخدام `npx wrangler login`.
5. نفّذ `npm run db:migrate` ثم `npm run check` ثم `npm run deploy`.
6. تحقق من `/api/health` و`/api/jobs` بعد أول حدث مجدول.

رابط Worker المستخدم للمشروع:
`https://mas3a-jobs-api.xn4wafc.workers.dev`
تم ربط المستودع بـ Cloudflare لبدء النشر التلقائي عند الدفع إلى فرع main.

## ربط واجهة الموقع لاحقًا

بعد التأكد من نجاح المزامنة، يوضع رابط Worker في `meta` باسم `masaa-api-base` في واجهة مَسعى، ويُضاف أصل Worker إلى `connect-src` في سياسة CSP. ملفات واجهة الموقع مستقلة عن هذا المستودع.

لا توجد مفاتيح API أو كلمات مرور مطلوبة لقراءة المصدرين العامين. ملفات الإعداد المحلية والأسرار مستثناة من Git.

تمت إعادة ربط النشر التلقائي مع Cloudflare.
